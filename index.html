1 Instalar VirtualBox
  1. Descarga VirtualBox:
    🌐 virtualbox.org/wiki/Downloads
  2. Activa Local Admin a través de ACME si es necesario
  3. Ejecuta el instalador con las opciones por defecto
  4. Usa tus credenciales A to Z si te pide permisos de administrador
Si tienes problemas con VirtualBox 7.x para adjuntar USB, usa la versión 6.1.x:
⬇️ VirtualBox 6.1.x (Old Builds)
2 Instalar Vagrant
  1. Descarga Vagrant:
    🌐 developer.hashicorp.com/vagrant/downloads
    Link directo Windows AMD64:
    ⬇️ vagrant_2.4.9_windows_amd64.msi
  2. Selecciona Windows AMD64
  3. Ejecuta el instalador con opciones por defecto
  4. ⚡ Reinicia el portátil (obligatorio)
El reinicio es obligatorio. Vagrant no funcionará correctamente sin reiniciar después de la instalación.
3 Descargar archivos de provisioning
  1. Accede a Amazon Drive (necesitas VPN):
    📂 OTIE ClientEng → Vagrant → usb_provisioning_image
  2. Descarga estos dos archivos:
    • usb_provisioning_image.box — imagen de la VM
    • Vagrantfile — configuración de la VM
4 Configurar estructura de carpetas

Vagrant necesita que los archivos estén organizados de una forma específica para funcionar. El archivo .box es la imagen de la VM y se usa solo una vez para importarla. El Vagrantfile es la configuración que Vagrant lee cada vez que lanzas la VM, y debe estar en su propia carpeta (usb_creator).

¿Por qué esta estructura? Vagrant crea archivos internos (carpeta .vagrant) en el mismo directorio donde está el Vagrantfile. Separar el .box del Vagrantfile mantiene todo limpio y evita conflictos.

Estructura final que debes tener:

📁 C:\Users\TU_USUARIO\Desktop\Thin Client\
    📄 usb_provisioning_image.box   ← descargado en Paso 3
    📁 vagrant\
        📁 usb_creator\   ← aquí se ejecutará vagrant up
            📄 Vagrantfile   ← descargado en Paso 3, movido aquí
            📁 .vagrant\   ← se creará automáticamente al ejecutar vagrant up

Paso a paso para crear la estructura:

Opción A — Con PowerShell (recomendado):

# 1. Abre PowerShell y ve a la carpeta donde descargaste los archivos
cd "$HOME\Desktop\Thin Client"

# 2. Verifica que los dos archivos descargados están aquí
dir
#    Deberías ver: usb_provisioning_image.box y Vagrantfile

# 3. Crea la subcarpeta vagrant\usb_creator
mkdir vagrant\usb_creator

# 4. Mueve SOLO el Vagrantfile a la subcarpeta usb_creator
mv Vagrantfile vagrant\usb_creator\

# 5. Verifica que todo quedó bien:
dir
#    Aquí solo debe quedar: usb_provisioning_image.box y la carpeta vagrant\

dir vagrant\usb_creator
#    Aquí debe estar: Vagrantfile

Opción B — Manualmente con el Explorador de archivos:

  1. Abre la carpeta Thin Client en tu Escritorio
  2. Dentro, crea una nueva carpeta llamada vagrant
  3. Dentro de vagrant, crea otra carpeta llamada usb_creator
  4. Arrastra el archivo Vagrantfile dentro de usb_creator
  5. El archivo usb_provisioning_image.box se queda en la raíz de Thin Client
No muevas el archivo usb_provisioning_image.box dentro de usb_creator. Debe quedarse en la carpeta principal Thin Client porque se referencia desde ahí en el Paso 5.
5 Añadir imagen Box a Vagrant

Desde PowerShell, en la carpeta Thin Client:

cd "$HOME\Desktop\Thin Client"
vagrant box add usb_provisioning_image.box --name usb_provisioning_image --force
Este proceso puede tardar varios minutos dependiendo del tamaño del archivo .box. No cierres la terminal.
6 Lanzar la VM de provisioning
  1. Navega a la carpeta usb_creator:
cd vagrant\usb_creator
  1. (Opcional) Destruye instancias anteriores:
vagrant destroy
  1. 🔒 Conéctate a la VPN (obligatorio en sites externalized)
  2. Lanza la VM:
vagrant up
VirtualBox se abrirá automáticamente. Si todo va bien, verás el menú de provisioning en la ventana de la VM.
7 Crear el USB de provisioning
  1. Inserta el USB directamente en el portátil (NO uses un hub USB)
  2. En VirtualBox, haz clic derecho en el icono USB de la barra inferior de la VM
  3. Selecciona tu USB para adjuntarlo a la VM (se desconecta del portátil)
  4. En el menú de la VM, configura:
    CampoValor
    Infra TypeFFNX (normalmente para sites externalized)
    Warehouse IDEl WHID de tu site
  5. Autentícate con Midway (Yubikey/Zukey)
  6. Espera a que termine (hasta 15 minutos)
Si tu site es co-located, usa siempre el WHID del site padre.
Cuando veas el mensaje de éxito, anota la fecha de expiración del USB. Una vez expirado, tendrás que crear uno nuevo.
8 Provisionar el Thin Client

8.1 — 🔓 Limpiar TPM

  1. Enciende el Thin Client y pulsa ESC para entrar en BIOS
  2. Navega a: Security → System Security → Clear TPM → Reset
  3. Pulsa F10 para guardar

8.2 — ⚙️ Aplicar defaults

  1. Ve a: File → Apply Defaults and Exit
  2. El TC se reiniciará automáticamente

8.3 — 🛡️ Desactivar Secure Boot y UEFI

  1. Pulsa ESC al reiniciar para volver a BIOS
  2. Navega a: Security → Secure Boot Configuration
  3. Pon Secure Boot = Disabled
Importante: Desactivar todo lo relacionado con UEFI. El USB de provisioning arranca en modo Legacy (no UEFI). Si dejas opciones UEFI activas, el TC no arrancará desde el USB correctamente.

8.4 — 🔄 Configurar Boot Mode a Legacy

  1. Navega a: Advanced → Boot Options (o Storage → Boot Order según modelo)
  2. Cambia Boot Mode de UEFI a Legacy (o CSM Boot si aparece esa opción)
  3. Si existe la opción UEFI Boot Sources, ponla en Disabled
  4. Asegúrate de que Legacy Boot Sources = Enabled
  5. En el Boot Order, coloca USB como primera opción de arranque
Resumen de lo que debe quedar desactivado:
  • ✗ Secure Boot = Disabled
  • ✗ UEFI Boot = Disabled
  • ✗ UEFI Boot Sources = Disabled
  • ✓ Legacy Boot = Enabled
  • ✓ USB Boot = Enabled y primero en el orden

8.5 — 📡 Desactivar WiFi (si va cableado)

  1. Navega a: Security → Slot Security → Slot 1 M.2 PCIe x1 = Disable
  2. Guarda con F10

8.6 — 🚀 Boot desde USB

  1. Inserta el USB de provisioning en el Thin Client
  2. Pulsa F9 para el menú de boot
  3. Selecciona el USB
  4. El provisioning se ejecutará automáticamente
Una vez completado, el Thin Client estará provisionado y listo para usar en la red externalized.

🔧 Solución de Problemas

Error de USB Controller al hacer vagrant up
→ Abre VirtualBox → Configuración de la VM → USB → Cambia a USB 1.1 (OHCI) Controller → Ejecuta vagrant up de nuevo.
Kernel Panic / Unsupported CPU (Windows 11)
→ Abre VirtualBox → Configuración de la VM → System → Processor → Aumenta a 2 CPUs → Ejecuta vagrant up de nuevo.
EDAMS Approval Not Obtained
→ Verifica que los 3 campos (site, image, use case) están correctamente configurados en TAKA antes de provisionar.
Provisioning Failure en el menú USB
→ Verifica: (1) USB no expirado, (2) BIOS correcta, (3) image en TAKA es externalized, (4) settings del TC no borrados.
TC acaba en 'asin282r' en vez de 'asin324r'
→ El infra override del USB no era ffnx. Recrea el USB con el infra type correcto.
Troubleshooting avanzado: En el menú USB del TC, elige "Drop To Shell" y ejecuta en secuencia:
sudo enroll_external_device.py
sudo set_external_iot_credentials.sh
sudo /usr/local/tce.installed/certifiget_client
sudo provision_client.sh
El primer comando que falle te indicará dónde está el problema.
